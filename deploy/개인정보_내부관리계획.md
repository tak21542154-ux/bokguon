**㈜올림포스네트웍스 전략사업실 유경탁 파트장**

「개인정보의 안전성 확보조치 기준」(개인정보보호위원회 고시 제2025-9호) **제4조**는 개인정보처리자가
개인정보의 안전한 처리를 위하여 내부 관리계획을 **수립·시행**하도록 정하고 있다.
이 문서는 그 의무를 이행하기 위한 계획서이며, 「복구온」 서비스에 적용된다.

## 제1조 (목적)

이 계획은 ㈜올림포스네트웍스(이하 "회사")가 운영하는 피해물 복구 중개 플랫폼 「복구온」에서
처리하는 개인정보가 분실·도난·유출·위조·변조 또는 훼손되지 않도록 안전성 확보에 필요한
기술적·관리적·물리적 조치를 정함을 목적으로 한다.

## 제2조 (적용 범위)

1. **대상 정보** — 「복구온」서비스가 수집·보관하는 모든 개인정보
   (보험사 담당자 성명·연락처·이메일, 협력업체 대표자 성명·연락처·이메일·**정산 계좌 정보**,
   서비스 이용 과정에서 자동 생성되는 접속 IP·접속 기록)
2. **대상 인원** — 회사의 임직원 중 개인정보를 처리하거나 접근 권한을 가진 자(이하 "취급자")
3. **대상 시스템** — 「복구온」 응용 서버, 데이터베이스, 백업 저장소, 관리자 콘솔

## 제3조 (개인정보 보호책임자의 지정) — 고시 제4조①1

| 구분 | 성명·직책 | 연락처 | 역할 |
|---|---|---|---|
| 개인정보 보호책임자 | `[ 성명 / 직책 ]` | `[ 연락처 ]` | 개인정보 처리 총괄, 처리방침 수립·공개, 유출 대응 지휘 |
| 개인정보 보호담당자 | 전략사업실 유경탁 파트장 | c.common@olymposnetworks.com | 계획 수립·점검, 취급자 권한 관리, 접속기록 점검 |

개인정보 보호책임자는 다음 업무를 수행한다.
1. 개인정보 처리에 관한 업무 총괄
2. 개인정보 처리 실태 및 관행의 정기적 조사·개선
3. 개인정보 처리와 관련한 불만 처리 및 피해 구제
4. 개인정보 유출 및 오·남용 방지를 위한 내부통제시스템 구축
5. 개인정보 보호 교육 계획 수립·시행
6. 개인정보 파일의 보호·관리·감독

## 제4조 (취급자의 역할 및 책임) — 고시 제4조①2

| 역할 | 대상 | 책임 |
|---|---|---|
| 최고관리자 | 개인정보 보호책임자가 지정한 1~2명 | 계좌 정보 열람·변경, 취급자 계정 발급·말소, 감사로그 점검 |
| 중간관리자 | 운영팀 책임자 | 사건·정산·하자 처리, 협력사 활성등록·검수판단 승인 등 주요 운영 결정. **계좌 정보 열람·변경 불가** |
| 하위관리자 | 운영팀 담당자 | 사건·정산·하자 처리 등 일상 업무 보조. 협력사 활성등록·검수판단 번복·**계좌 정보 열람·변경 불가** |
| 협력업체 | 입점 승인 업체 | 자사 데이터만 조회. 타사 정보 접근 불가 |
| 보험사 | 계약 기관 | 자사 사건만 조회. 타사 사건·입찰가 접근 불가 |

취급자는 다음을 준수한다.
1. 업무상 알게 된 개인정보를 누설하거나 권한 없이 이용하지 않는다.
2. 부여받은 계정을 타인과 공유하지 않는다.
3. 개인정보를 개인 저장매체·개인 메일·메신저로 반출하지 않는다.
4. 개인정보 유출이 의심되면 즉시 개인정보 보호책임자에게 보고한다.

## 제5조 (접근 권한의 관리) — 고시 제5조

1. 개인정보에 대한 접근 권한은 **업무 수행에 필요한 최소한의 범위**로 차등 부여한다.
2. 취급자가 전보·퇴직 등으로 변경되면 **지체 없이(늦어도 5일 이내)** 권한을 변경하거나 말소한다.
3. 권한 부여·변경·말소 내역은 **3년 이상** 보관한다.
4. 계정은 **1인 1계정**을 원칙으로 하며 공용 계정을 사용하지 않는다.
5. 비밀번호는 다음 규칙을 강제한다(시스템에서 자동 검증).
   - 영문·숫자·특수문자 중 **2종 이상 조합 시 10자리 이상**, **3종 이상 조합 시 8자리 이상**
   - 아이디와 동일한 문자열, 동일 문자 4회 이상 연속 사용 금지
   - **최초 발급 비밀번호는 최초 로그인 시 변경이 강제**된다(변경 전 다른 화면 이용 불가)
6. 비밀번호는 **복호화되지 않는 일방향 함수**(PBKDF2-HMAC-SHA256, 60만 회 반복 + 임의 솔트)로 저장한다.
7. 인증 실패가 **5회 연속** 발생하면 해당 계정·IP 조합을 **10분간 잠근다.**

## 제6조 (접근 통제) — 고시 제6조

1. 관리자 콘솔(`/admin`)은 **사무실 고정 IP 등 지정된 대역에서만** 접속할 수 있도록 제한한다
   (환경변수 `BOKGUON_ADMIN_IP_ALLOW` + nginx `allow/deny`).
   - 판정 기준 IP 는 신뢰하는 리버스 프록시가 확인한 값만 사용한다(요청 헤더 위조 방지).
2. 인터넷 구간은 **HTTPS(TLS 1.2 이상)** 로만 서비스하며, HTTP 접속은 HTTPS 로 강제 전환한다.
3. 응용 서버는 **외부에서 직접 접근할 수 없도록** 127.0.0.1 에만 바인딩하고, 방화벽에서
   22(SSH)·80·443 외 모든 포트를 차단한다.
4. **30분간 활동이 없으면 세션을 자동 종료**하고, 로그인 시 세션 식별자를 재발급한다.
5. 각 주체(관리자·협력업체·보험사)는 **세션에 기록된 자기 식별자로만** 데이터를 조회한다.
   요청 파라미터로 타인의 자원을 지정해도 서버가 소유권을 다시 확인한다.

## 제7조 (개인정보의 암호화) — 고시 제7조

| 대상 | 조치 | 근거 |
|---|---|---|
| 비밀번호 | PBKDF2-HMAC-SHA256 60만 회 + 임의 솔트 (일방향) | 고시 제7조 제4항 |
| **정산 계좌번호** | **AES-256-GCM 암호화 저장.** 목록 화면은 마스킹 표시, 원문 열람은 최고관리자만 가능하며 열람 사실을 감사로그에 기록 | 고시 제7조 제2항 |
| 전송 구간 | TLS 1.2 이상, HSTS 적용 | 고시 제7조 제1항 |
| 암호화 키 | 데이터베이스와 **분리된 환경변수**(.env, 권한 600)로 관리. 별도 보관처에 사본 보관 | 고시 제7조 제6항 |

> ⚠ 암호화 키(`BOKGUON_ENC_KEY`)를 분실하면 저장된 계좌번호를 **영구히 복호화할 수 없다.**
> 키는 회사 비밀번호 관리자에 사본을 보관하고, 담당자 퇴직 시 인수인계 대상에 포함한다.

## 제8조 (접속기록의 보관 및 점검) — 고시 제8조

1. 개인정보 취급자의 접속기록(계정, 접속일시, 접속지 IP, 수행 업무)을 **2년 이상** 보관한다.
   - 「복구온」은 5만 명 이상의 정보주체 정보를 처리할 수 있고 계좌 정보를 다루므로 2년을 적용한다.
2. 접속기록은 **월 1회 이상** 점검한다. 특히 다음을 확인한다.
   - 계좌 정보 열람·변경 이력
   - 비정상 시간대·비정상 IP 접속
   - 대량 조회·다운로드
3. 접속기록이 위·변조·도난·분실되지 않도록 별도 저장장치에 백업한다.
4. **보관 기간이 지난 접속기록은 파기**한다(주 1회 자동 실행: `manage.py prune-logs`).

## 제9조 (악성프로그램 등 방지) — 고시 제9조

1. 서버 운영체제와 응용 프로그램의 보안 업데이트를 **월 1회 이상** 적용한다.
2. 의존 라이브러리는 버전을 고정(`requirements.txt`)하고, 알려진 취약점 공지를 분기 1회 확인한다.
3. 업로드 파일은 크기(장당 8MB, 요청 전체 `BOKGUON_MAX_UPLOAD_MB` 설정값)와 형식(사진: JPEG·PNG·WEBP·HEIC — 실제 파일 시그니처로 판정, 확장자만으로 판정하지 않음)을 제한한다.

## 제10조 (물리적 안전조치) — 고시 제10조

1. 서버는 국내 클라우드 사업자의 데이터센터에 두며, 물리적 접근통제는 해당 사업자의 조치에 따른다.
2. 개인정보가 포함된 서류·저장매체는 잠금장치가 있는 장소에 보관한다.
3. 개인정보를 개인 저장매체(USB 등)에 반출하지 않는다.

## 제11조 (재해·재난 대비) — 고시 제11조

1. **매일 새벽 3시** 데이터베이스를 백업하고, 백업본의 무결성을 자동 검증한다.
2. 백업본은 **30일간** 보관하며, 소유자만 접근할 수 있도록 권한을 제한한다(0600).
3. **분기 1회** 백업본으로 복구가 실제로 되는지 리허설한다(`manage.py restore`).
4. 백업본에도 개인정보가 포함되므로, 외부로 반출할 때는 암호화한다.

## 제12조 (개인정보의 파기) — 개인정보 보호법 제21조

1. 보유 기간이 지나거나 처리 목적이 달성된 개인정보는 **지체 없이** 파기한다.
2. 전자적 파일은 복구·재생할 수 없는 방법으로 삭제하고, 종이 문서는 분쇄 또는 소각한다.
3. 파기 대상·시기·방법은 개인정보 처리방침 제3조·제4조에 공개한다.

## 제13조 (개인정보 유출 사고 대응) — 개인정보 보호법 제34조

유출을 인지한 즉시 다음 절차를 따른다.

| 단계 | 시한 | 조치 |
|---|---|---|
| 1. 인지·보고 | 즉시 | 발견자 → 개인정보 보호책임자 보고, 추가 유출 차단(계정 정지·접근 차단) |
| 2. 사실 확인 | 24시간 이내 | 유출 항목·시점·규모·원인 파악, 접속기록 보전 |
| 3. 정보주체 통지 | **72시간 이내** | 유출 항목·시점·경위, 피해 최소화 방법, 대응 조치, 담당 부서 연락처 통지 |
| 4. 신고 | **72시간 이내** | 1천 명 이상 유출 시 개인정보보호위원회 또는 한국인터넷진흥원에 신고 |
| 5. 재발 방지 | 30일 이내 | 원인 제거, 내부 관리계획 개정, 취급자 교육 |

## 제14조 (개인정보 보호 교육) — 고시 제4조①8

1. 전 취급자를 대상으로 **연 1회 이상**, 회당 2시간 이상 교육을 시행한다.
2. 신규 취급자는 업무 배치 후 **1개월 이내** 교육을 받는다.
3. 교육 내용 — 개인정보 보호법 개요, 취급자의 의무와 책임, 계정·비밀번호 관리,
   유출 사고 대응 절차, 실제 사고 사례.
4. 교육 실시 기록(일시·대상·내용·참석자)을 **3년간** 보관한다.

## 제15조 (수탁자 관리·감독) — 개인정보 보호법 제26조

1. 개인정보 처리 업무를 위탁할 때는 위탁 계약서에 다음을 명시한다.
   - 위탁 업무 목적 외 처리 금지, 기술적·관리적 보호조치, 재위탁 제한,
     수탁자에 대한 관리·감독, 손해배상 책임
2. 수탁자와 위탁 업무 내용을 개인정보 처리방침에 공개한다.
3. **연 1회 이상** 수탁자의 개인정보 보호조치 이행 여부를 점검한다.

## 제16조 (이행 점검) — 고시 제4조③

1. 개인정보 보호책임자는 **연 1회 이상** 이 계획의 이행 실태를 점검하고 결과를 대표이사에게 보고한다.
2. 점검에는 다음 자동 점검 도구를 활용한다.
   ```
   python manage.py check        # 시크릿 설정·기본 비밀번호·백업 상태 점검
   python smoke_test.py https://도메인   # 접근통제·권한 격리 실동작 확인
   ```
3. 점검 결과 미비 사항은 개선 계획을 세워 조치하고, 그 결과를 기록·보관한다.
