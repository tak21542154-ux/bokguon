## 0. 왜 꺼지는가
- Codespaces는 **30분 무활동 시 자동 종료(Shutdown)** 된다.
- 종료되면 ① gunicorn 서버 ② 포트 포워딩 ③ VS Code 서버(터널 릴레이)가 모두 죽는다.
- 재시작 후에는 **포트 가시성이 private으로 초기화**되므로 public 재설정이 필요하다.

## 1. 복구 절차 (약 5분)

```bash
# 1) 코드스페이스 부팅 (SSH가 자동 시작시킴)
gh codespace ssh -c psychic-capybara-jj6q9qxj5grph494

# 2) 서버 기동 (gunicorn 전체경로 주의 — PATH에 없음)
cd /workspaces/bokguon
nohup /home/codespace/.local/lib/python3.14/site-packages/bin/gunicorn \
  -c gunicorn_conf.py wsgi:application >> logs/gunicorn_out.log 2>&1 &

# 3) 포트 등록 + 공개 전환 (등록 명령은 백그라운드 유지)
gh codespace ports forward 8771:8771 -c psychic-capybara-jj6q9qxj5grph494
gh codespace ports visibility 8771:public -c psychic-capybara-jj6q9qxj5grph494

# 4) 웹 에디터를 1회 열어 VS Code 서버(=터널 릴레이)를 살린다
gh codespace code --web -c psychic-capybara-jj6q9qxj5grph494

# 5) 확인
curl -o /dev/null -w "%{http_code}" https://psychic-capybara-jj6q9qxj5grph494-8771.app.github.dev/
```

## 2. 알려진 이슈 — 한국에서 404 (2026-10-13 기록)
- 한국 DNS는 GitHub 터널의 **일본 클러스터**로 안내하는데, 이 코드스페이스의
  릴레이 라우트가 일본 클러스터에 반영되지 않아 **빈 404**가 반환된다. (GitHub 인프라 이슈)
- **정상 클러스터(동남아시아)로 강제하면 200 정상**:
  ```bash
  curl --resolve psychic-capybara-jj6q9qxj5grph494-8771.app.github.dev:443:20.197.80.108 \
       -o /dev/null -w "%{http_code}" https://psychic-capybara-jj6q9qxj5grph494-8771.app.github.dev/
  ```
- **토니 PC 대응**: 바탕화면 `복구온_공식URL_접속설정.bat` 실행 (hosts 한 줄 브릿지, 관리자).
  - IP가 바뀌면: 코드스페이스 안에서 `getent hosts ...-8771.app.github.dev` 로 현재 IP 확인 후 hosts 수정.

## 3. 외부 공유용 예비 터널 (Cloudflare)
- GitHub 라우팅이 완전히 정상화되기 전까지, **외부(협력사/보험사) 테스터**에게는
  Cloudflare 터널 주소를 병행 안내한다. (한국 포함 전 세계 즉시 접속 가능)
- 코드스페이스 안에서:
  ```bash
  cd ~/bin && nohup ./cloudflared tunnel --url http://127.0.0.1:8771 --no-autoupdate > ~/cloudflared.log 2>&1 &
  sleep 15 && grep -o -E 'https://[a-z0-9-]+\.trycloudflare\.com' ~/cloudflared.log | head -1
  ```
- 발급된 `*.trycloudflare.com` 주소는 **재시작마다 바뀐다**. (첫 방문 신뢰 경고 없음)
