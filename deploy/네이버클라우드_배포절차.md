# 복구온 — 네이버클라우드 배포 절차

**㈜올림포스네트웍스 전략사업실 유경탁 파트장**

이 문서는 **서버가 없는 상태**에서 시작해 서비스가 뜰 때까지를 순서대로 적은 것이다.
서버 생성·결제는 계정 권한이 필요하므로 사람이 직접 해야 하고, 그 뒤 설치는 스크립트가 한다.

> 소요 시간: 서버 생성 약 10분 + 설치 약 10분 + 오픈 절차 약 5분.
> 준비물: 네이버클라우드 계정, 도메인 1개.

---

## 1단계 — 서버 만들기 (콘솔에서)

네이버클라우드 콘솔 → **Server** → 서버 생성.

| 항목 | 값 | 이유 |
|---|---|---|
| 서버 이미지 | **Ubuntu Server 24.04 LTS** | 설치 스크립트가 apt 기준. 22.04 도 동작한다 |
| 서버 타입 | vCPU 2 / 메모리 4GB 이상 | 사진 변환(HEIC→JPEG)이 메모리를 쓴다. 2GB 는 빠듯하다 |
| 스토리지 | 50GB 이상 | 시공 사진이 쌓인다. 사건당 최대 300MB 상한 기준 |
| 요금제 | 월요금제 | 상시 가동 서비스다 |
| 인증키 | 새로 생성 후 **`.pem` 파일 안전 보관** | 분실하면 서버에 못 들어간다 |

> 리전은 **한국(KR)** 을 쓴다. 국외 리전을 쓰면 개인정보 국외이전 고지·동의 절차가 별도로 필요해진다.

### 공인 IP 연결
서버 생성 후 **Public IP** 를 신청해 서버에 연결한다. 이게 없으면 외부에서 접속할 수 없다.

### ACG(방화벽) 규칙 — **가장 많이 빠뜨리는 단계**
**Server → ACG → 규칙 설정**에서 아래 3개를 **Inbound** 로 추가한다.

| 프로토콜 | 접근 소스 | 허용 포트 | 용도 |
|---|---|---|---|
| TCP | **사무실 고정 IP/32** | 22 | SSH 관리 접속 |
| TCP | 0.0.0.0/0 | 80 | 인증서 발급 + HTTPS 리다이렉트 |
| TCP | 0.0.0.0/0 | 443 | 실제 서비스 |

> **22번을 0.0.0.0/0 으로 열지 말 것.** 공개된 SSH 는 몇 시간 안에 자동 공격을 받는다.
> 8771(앱 포트)은 **열지 않는다.** 앱은 127.0.0.1 에만 바인딩되고 외부는 nginx 가 받는다.

## 2단계 — 도메인 연결

도메인 관리 화면에서 **A 레코드**를 서버 공인 IP 로 지정한다.

```
bokguon.olymposnetworks.com.   A   <서버 공인 IP>
```

> ⚠ **DNS 전파가 끝난 뒤에** 3단계로 간다. 전파 전에 설치하면 인증서 발급이 실패한다.
> 확인: `nslookup bokguon.olymposnetworks.com` 이 서버 IP 를 돌려주면 준비 완료.

## 3단계 — 소스 올리고 설치 (한 번에 끝난다)

내 PC에서:

> ### ⚠ 묶음은 **올리기 직전에 새로 만든다**
> 바탕화면 등에 예전에 만들어 둔 배포 묶음(예: `260721_복구온_배포묶음.tar.gz` 류
> 날짜가 박힌 파일)을 재사용하지 말 것 — 실제로 그런 옛 묶음의 `app.py` 가 현재
> 소스의 3분의 1 크기였고 `dispatch.py`·`compliance.py`·`notify_popbill.py`·
> `partner_accounts.py` 가 통째로 빠져 있던 사고가 있었다(AWS_배포절차.md 92행
> 참고). 겉으로는 설치가 성공하고, 없는 기능은 조용히 없다.

```bash
# 개발용 DB·시크릿·로그는 빼고 올린다 (섞이면 데모 계정이 운영으로 넘어간다)
tar --exclude='*.db*' --exclude='.env' --exclude='*.log' --exclude='logs' \
    --exclude='backups' --exclude='uploads' --exclude='__pycache__' --exclude='dev_*.pem' \
    -czf bokguon_deploy.tar.gz bokguon_service/

# 담겼는지 확인한다 — 목록에 이 파일들이 전부 있어야 한다(7줄 나와야 정상)
tar -tzf bokguon_deploy.tar.gz | \
    grep -E 'bokguon_service/(app|db|manage|dispatch|compliance|notify_popbill|partner_accounts)\.py$'

scp -i <인증키>.pem bokguon_deploy.tar.gz ubuntu@<서버IP>:~/
```

서버에서:

```bash
ssh -i <인증키>.pem ubuntu@<서버IP>
tar -xzf bokguon_deploy.tar.gz
cd bokguon_service

sudo BOKGUON_DOMAIN=bokguon.olymposnetworks.com \
     BOKGUON_EMAIL=c.common@olymposnetworks.com \
     bash deploy/bootstrap.sh
```

`bootstrap.sh` 가 하는 일 — 전용 계정 생성 → 가상환경·의존성 → **시크릿 자동 생성** →
DB 초기화 → 협력업체 398개사 적재 → systemd 등록 → nginx → **Let's Encrypt 인증서** →
방화벽 → 크론(5분마다 **예약 실행** · 백업 · 사진백업 · 로그정리 · 개인정보 파기) →
점검 → 스모크 테스트.

> ⚠ 예약 실행(`manage.py sweep`)이 크론에 없으면 서비스가 반쯤 죽은 채로 돕니다 —
> 경매가 마감되지 않고, 출동 기한이 지나도 재수배가 안 되고, 문자·알림톡이 발송대기로만
> 쌓입니다. 배포 후 `manage.py check` 가 이걸 봅니다.

여러 번 실행해도 안전하다. **`.env` 와 기존 DB 는 절대 덮어쓰지 않는다.**

### 설치 직후 즉시 할 것 — 이 두 개를 놓치면 복구 불가
1. 출력된 **`BOKGUON_ENC_KEY`** 를 회사 비밀번호 관리자에 보관.
   **이 키를 잃으면 저장된 정산 계좌번호를 영구히 복호화할 수 없다.**
2. 출력된 **최고관리자 임시 비밀번호**를 안전한 경로로 전달(최초 로그인 시 변경 강제).

## 4단계 — 관리자 접속 IP 지정

```bash
sudo nano /opt/bokguon/.env
```

`BOKGUON_ADMIN_IP_ALLOW` 에 **사무실 고정 IP** 를 넣는다(쉼표로 여러 개 가능).
처리방침에 "관리자 콘솔 IP 제한 시행"을 고지했으므로 비워 두면 고지와 어긋난다.
`manage.py check` 도 비어 있으면 배포 불가로 막는다.

> ⚠ Windows 메모장·PowerShell 은 파일 앞에 BOM 을 붙인다 — 앱은 이제 BOM 을 걸러내도록
> 고쳐 뒀지만(305라운드), 다른 도구가 이 파일을 읽을 때 여전히 문제가 될 수 있다.
> `nano`/`vi` 권장.

## 5단계 — 오픈 절차

`deploy/DEPLOY.md` **0장 "오픈 당일 순서"** 를 그대로 따른다. 요약하면:

```bash
cd /opt/bokguon

# 1) 회사 정보 — 7건은 이미 채워져 있다(company_info.json 이 소스와 함께 올라감).
#    남은 것은 PG 뿐이다. 계약 전이면 비워 두고, 정산 개시 전까지 채운다.
./venv/bin/python manage.py show-info
#  ⚠⚠ [라운드308] company_info.json 의 hosting 값이 "아마존웹서비스(AWS) — 서울
#    리전"으로 박혀 있다(원래 AWS 배포 기준으로 채운 값) — 이 값은 /legal/privacy
#    공개 페이지에 수탁자로 그대로 노출된다. 네이버클라우드에 배포하면서 이 값을
#    안 고치면, 실제로는 네이버클라우드에서 도는데 공개 처리방침엔 AWS라고 거짓
#    고지하게 된다(manage.py check 의 미기재 판정은 "값이 있는지"만 보므로 이
#    오기재를 못 잡는다 — 정상적인 문자열이라 통과로 나온다). 아래로 바로잡는다:
./venv/bin/python manage.py set-info hosting "네이버클라우드"

# 2) 실제 관리자 계정을 **먼저** 만든다 (아이디에 admin·staff 금지)
./venv/bin/python manage.py create-admin ktyu --name 유경탁 --role 최고관리자

# 3) 데모 정리 (운영 DB 는 애초에 시드가 없어 대개 "정리할 데모 없음"으로 끝난다)
./venv/bin/python manage.py go-live --yes

# 4) 점검 — "배포 가능" 이 떠야 한다
./venv/bin/python manage.py check

# 5) 재시작 + 실동작 검증
sudo systemctl restart bokguon
#  ⚠⚠ [라운드308] 이 세 줄이 없으면 smoke_test.py 는 검사를 단 하나도 실행하지
#    않고 종료코드 2 로 끝난다(공개면·보안헤더 검사까지 전부 포함해서 안 돈다) —
#    "로그인만 건너뛴다"가 아니라 "아무것도 안 돈다". DEPLOY.md 가 125·285라운드
#    에서 이미 겪은 함정과 같다.
export BOKGUON_TEST_ADMIN_PW="bokguon2026"
export BOKGUON_TEST_INSURER_PW="bokguon2026"
export BOKGUON_TEST_PARTNER_PW="partner2026"
./venv/bin/python smoke_test.py https://bokguon.olymposnetworks.com
unset BOKGUON_TEST_ADMIN_PW BOKGUON_TEST_INSURER_PW BOKGUON_TEST_PARTNER_PW
```

> 위 3단계(go-live)가 admin/partner/insurer 데모 계정을 이미 지웠으므로, 비밀번호를
> 넣어도 로그인 이후 검사(CSRF·입찰·정산 등)는 대부분 건너뛰고 종료코드 4 가 뜬다 —
> 이 시점에는 정상이다(공개면·보안헤더·법정문서·레이트리밋은 그래도 검증된다).
> 종료코드 0(전부 통과)을 다시 보려면 운영용 검증 계정을 별도로 만들어 실행할 것.

## 6단계 — 오픈 후 확인

| 확인 | 방법 |
|---|---|
| HTTPS 정상 | 브라우저에서 자물쇠 표시, `http://` 접속 시 자동 전환 |
| 법정 게시물 | `/legal/privacy` 에 "(미기재)" 가 남아 있지 않은지 |
| 백업 동작 | 다음 날 `/opt/bokguon/backups/` 에 파일이 생겼는지 |
| 사진 백업 | `uploads/` 가 백업 경로에 복사되는지 (DB 백업과 별개다) |
| 인증서 자동갱신 | `sudo systemctl status certbot.timer` |

## 알아둘 것

- **PG 미정 상태로도 서비스는 뜬다.** 입찰·시공·사진검수까지 정상 동작한다.
  다만 **정산 이체 단계 전까지** PG 계약을 마치고 `set-info pg` 로 채워야 한다.
- **알림톡은 아직 나가지 않는다.** 팝빌((주)링크허브) 연동신청·채널개설·템플릿 승인이 끝나야
  실제 발송이 시작된다. 그전까지 알림은 '발송대기'로 쌓이고 어드민 운영알림 화면에서 확인한다.
- **데이터베이스는 SQLite 단일 서버 전제다.** 서버를 늘리려면 PostgreSQL 이전이 먼저다.

## 사고 시 되돌리기

```bash
sudo systemctl stop bokguon
cd /opt/bokguon
# ⚠ 백업 위치는 .env 의 BOKGUON_BACKUP_DIR 가 정한다(bootstrap.sh 가 써 넣는다).
#   클라우드 기본값은 /var/backups/bokguon 이며 `backups/` 상대경로는 없다 —
#   장애 상황에서 상대경로로 치면 "파일이 없습니다" 로 끝난다. 위치부터 확인한다.
ls -lt "$(grep -oP '(?<=^BOKGUON_BACKUP_DIR=).*' .env || echo /var/backups/bokguon)" | head
./venv/bin/python manage.py restore /var/backups/bokguon/bokguon_<날짜>.db --yes
sudo systemctl start bokguon
```

> 백업은 **DB만** 뜬다. 사진은 `uploads/` 별도 백업에서 되돌린다.
