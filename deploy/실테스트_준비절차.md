# 실테스트 준비 절차 — 순서를 지켜야 합니다

㈜올림포스네트웍스 전략사업실 유경탁 파트장 · 2026-08-03

> **⚠ 가장 중요한 것** — `go-live` 는 현재 관리자 계정 **admin·staff 를 삭제**합니다.
> 먼저 실계정을 만들지 않으면 **콘솔에 아무도 못 들어갑니다.**
> 아래 순서를 그대로 따르십시오.

---

## 왜 준비가 필요한가 (실측)

실제 운영 DB를 조회한 결과입니다.

| 항목 | 현재 | 문제 |
|---|---|---|
| 보험사 실계정 | **0개** (6곳 전부 데모) | 담당자가 로그인할 수단이 없음 |
| 협력사 포털 계정 | **1곳** / 399곳 | 출동 콜을 받아도 **수락할 사람이 없음** |
| 협력사 휴대전화 | 68곳 (17%) | 나머지는 유선번호 → 문자·알림톡 불가 |
| 협력사 정산 계좌 | **0곳** | 정산 마지막 단계에서 반드시 멈춤 |
| 협력사 좌표 | 365곳 (91%) ✔ | 2026-08-03 정비 완료 |
| 스모크 테스트 잔재 | 사건 58건·정산 29건(9,650만원) | `is_demo=0` 이라 go-live 로도 안 지워짐 |

**막는 것은 전부 준비 작업이고, 코드 결함이 아닙니다.**

## 순서

### ⓪ 먼저 지금 상태부터 봅니다

```bash
python manage.py check
```

한 번에 알려 줍니다 — 실계정 유무, 데모 데이터 잔존, **지급 계좌 없는 협력사 명단**,
**2시간 넘게 발송되지 않은 알림과 그 원인**, 예약 실행이 실제로 돌고 있는지.
아래 ①~⑨ 를 마친 뒤 다시 돌려 **"배포 가능"** 이 뜨는지 확인하십시오.


### ① 실관리자 계정 먼저 (이걸 건너뛰면 콘솔이 잠깁니다)

```bash
python manage.py create-admin <실담당자아이디> --role 최고관리자
```

`admin`·`staff` 가 **아닌** 아이디로 만드십시오. 그 둘은 go-live 삭제 대상입니다.

> `--role` 은 **최고관리자 · 중간관리자 · 하위관리자** 셋 중 하나여야 합니다.
> 다른 값을 넣으면 이제 명령이 거부합니다. 2026-08-05 이전에는 기본값이
> `운영관리자` 였는데 그런 등급이 없어서, **로그인은 되는데 아무 기능도 못 쓰는**
> 계정이 만들어졌습니다. 그 계정으로 발급했다면 등급을 다시 지정하십시오.

### ② 스모크 잔재에 데모 표식 붙이기

go-live 는 `is_demo=1` 인 행만 지웁니다. 스모크가 만든 것들은 표식이 없어 살아남습니다.

```bash
python manage.py mark-smoke-demo --dry
```

미리보기로 대상을 확인한 뒤 `--dry` 없이 실행하십시오.

### ③ go-live 실행

```bash
python manage.py go-live --yes
```

데모 보험사 6곳(메리츠·DB·KB 포함)과 데모 계정이 사라집니다.
**보험사 담당자 앞에서 경쟁사가 「계약중」으로 보이는 상황이 여기서 정리됩니다.**

> **2026-08-05 변경 — 두 가지가 달라졌습니다.**
> · 종전에는 데모가 0건이어도 **알림을 전량 삭제**했습니다(기준 시각이 '지금'이라
>   전부 걸렸습니다). 발송대기 중이던 문자·알림톡이 사라져 영영 안 나갔습니다.
>   이제 **데모 사건에 딸린 알림과 데모 표식이 붙은 알림만** 지웁니다.
> · 사건에 딸린 **출동수배·현장합의·변경견적**도 함께 지웁니다. 종전에는 남아
>   없어진 사건을 가리키는 고아 행이 됐고, 배포 점검은 그걸 못 보고 초록이었습니다.
>   이제 `manage.py check` 가 고아 행을 경고합니다.

### ④ 보험사 실계정 만들기

```bash
python manage.py create-insurer "<실제 기관명>" <아이디> <요율%>
```

### ⑤ 협력사 계정 발급 — 테스트에 부를 곳만

```bash
python partner_accounts.py --dry --region 서울 --major 가드레일 --limit 8
python partner_accounts.py --region 서울 --major 가드레일 --limit 8 --out 계정.csv
```

- 최소 **시행사 3곳**(경매 최소 참여 3개사) + **출동 후보 5곳**
- 임시 비밀번호는 첫 로그인에 반드시 바뀝니다
- `--out` 파일은 전달 후 지우십시오

콘솔에서 한 곳씩 발급할 때는 **[업체] → 업체 클릭 → 계정 발급** 을 쓰십시오.
발급 직후 뜨는 **「안내문 복사」** 버튼을 누르면 접속 주소·아이디·임시 비밀번호와
앱 설치·계좌 등록 안내가 한 문단으로 복사됩니다. 그대로 붙여 보내면 됩니다.

### ⑤-2 담당자 계정 등급 — 「조회」로 줄 사람과 아닌 사람

보험사·협력사 **원계정**은 포털에서 담당자 계정을 만들 수 있고, 등급이 둘입니다.

| 등급 | 할 수 있는 것 |
|---|---|
| 중간관리자 | 조회 + **낙찰 승인·완료 승인·사건 취소·입찰 제출** |
| 하위관리자(조회·접수) | 조회 + 접수만. 돈이 확정되는 동작은 **서버가 막습니다** |

낙찰 승인은 곧 계약 성립입니다. **결재 권한이 없는 담당자에게는 반드시 하위관리자로** 발급하십시오.
(2026-08-05 이전에는 이 경계가 서버에 없어 조회 계정도 승인이 됐습니다 — 지금은 화면에서 버튼이
사라지고 서버도 403 으로 거부합니다.)

### ⑤-3 협력사에 미리 알려 둘 것

첫 주에 전화가 가장 많이 오는 지점들입니다.

| 상황 | 화면이 하는 말 |
|---|---|
| 사진 없이 완료 보고 | 버튼이 잠기고 「사진을 먼저 올려 주세요」 |
| 신호가 끊긴 곳에서 사진 업로드 | 기기에 저장돼 있다가 신호가 오면 자동 재시도 |
| 2차 공고에 상한이 없음 | 「최소 금액」 아래로만 못 넣고 위로는 제한 없음 |
| 남의 견적·낙찰가가 안 보임 | 원칙입니다 — 사진과 최소 금액만 보고 정하는 구조 |

### ⑥ 그 업체들 정보 채우기 (콘솔에서)

- **담당자 휴대전화**(010) — 유선번호로는 문자가 못 나갑니다
- **정산 계좌** — 없으면 지급 단계에서 막힙니다
- **주소** — 마이페이지에서 「주소 검색」으로 고르면 좌표가 정확해집니다

### ⑦ 예약 실행 등록 확인

```bash
python manage.py sweep
```

작업 스케줄러에 이 명령이 **자동 실행**으로 등록돼 있어야 합니다.
이게 안 돌면 입찰 마감·출동 기한·완료보고 지연·승인 독촉이 전부 멈춥니다.
대시보드 상단 배지가 이 명령의 실행 시각을 보여 줍니다.

이 PC에는 `복구온_경매마감`·`복구온_일일백업` 두 작업이 **이미 등록돼 정상 실행 중**입니다
(2026-08-05 확인). 새 PC로 옮길 때만 아래를 실행하십시오.

```bash
powershell -ExecutionPolicy Bypass -File deploy/복구온_예약실행_등록.ps1 -RunNow
```

> **AWS 서버로 옮길 때** — `bootstrap.sh` 가 `/etc/cron.d/bokguon` 에 5분 주기로
> 넣어 줍니다(2026-08-05 추가). 그 전 버전으로 배포한 서버라면 이 줄이 **없어서**
> 서비스가 반쯤 죽은 채로 돕니다. `manage.py check` 가 이제 그걸 잡아냅니다.

### ⑦-2 무등록 업체는 자동으로 빠집니다

협력사 상세의 「건설업 등록 조사」를 **무등록**으로 저장하면 그 업체는
입찰과 출동 수배에서 자동으로 제외됩니다(건설산업기본법 제25조 제2항).
아직 조사하지 않은 **미확인**은 막지 않습니다 — 확인된 사실만 근거로 씁니다.

### ⑧ (선택) 문자·알림톡 켜기

`.env` 에 아래 5개를 채우고 재시작하면 실제로 문자가 나갑니다.

```
BOKGUON_NOTIFY_ENABLED=1
POPBILL_LINK_ID=...
POPBILL_SECRET_KEY=...
POPBILL_CORP_NUM=...
POPBILL_SENDER=...
POPBILL_TEST=1      ← 테스트베드. 과금·실수신 없이 전 구간 점검 가능
```

**켜지 않으면** 모든 문자·알림톡이 발송대기함에만 쌓입니다(화면이 그렇게 표시합니다).
켤 계획이면 **테스트베드(POPBILL_TEST=1)로 먼저** 돌려 보십시오.

> 켜기 전까지 실테스트를 돌린다면 — 콘솔 **[발송 대기함]** 에 수신자 이름과
> **전화번호**가 함께 나옵니다. 번호를 눌러 바로 걸고, 알린 뒤 「처리함」으로 닫으십시오.
> 앱을 켜 둔 업체는 포털 종 알림으로도 보입니다(문자만 안 나갈 뿐입니다).

⚠ 발신번호는 **테스트베드에도 따로 등록**해야 하며 통신사 심사에 1~2일 걸립니다.
키를 받는 즉시 등록부터 신청하십시오.

### ⑨ 접속 도메인 허용

`.env` 의 `BOKGUON_ALLOWED_HOSTS` 에 실제 접속 주소를 넣으십시오.
목록에 없는 주소로 들어오면 요청이 통째로 막힙니다.

## 테스트 시나리오 (2차 트랙 — 이 플랫폼의 차별점)

1. 보험사 담당자가 **사진 없이** 사건 접수 (가견적 300만)
2. 운영자가 출동 수배 → 화면이 「앱에서 수락 가능 N곳」을 알려 줍니다
3. 협력사가 폰으로 수락 → **현장 사진 찍기** → 도착 보고(실견적 500만)
4. 보험사 부동의 → **2차 경매**(가견적 300만이 **하한**, 상한 없음)
5. 협력사들이 사진 보고 입찰 → 최저가 낙찰
6. 보험사 승인 → 시공 → 완료 보고 → 검수 → 정산

각 단계에서 **현장 출동 보고서**(사건 상세 → 📄)를 뽑아 보십시오.
호출 이력·실견적·사진이 한 장에 모입니다.

## 첫날에 자주 밟는 지점

- **발주처를 먼저 등록해야 사건을 올릴 수 있습니다.** 발주처가 0곳이면 등록 화면이 빨간 안내와
  「발주처 등록하러 가기」 버튼을 띄웁니다.
- **참여 가능한 시행사가 0곳이면** 공고를 열어도 마감 때 유찰됩니다. 이제 그 순간 운영팀 알림이
  뜨니, 계정을 발급하거나 출동 수배로 전환하십시오.
- **금액 칸은 한글로 읽어 줍니다** — 가견적에 `3600000` 을 넣으면 「360만원」이 함께 보이고,
  10만 원 미만·1억 원 이상이면 경고가 붙습니다. 제출 직전 한 번 더 확인창이 뜹니다.
- **낙찰 승인은 추천이 미리 선택돼 있지 않습니다.** 반드시 업체를 직접 고르셔야 합니다
  (추천은 참고 표시일 뿐이고, 자동화가 낙찰을 정하지 않는다는 원칙 때문입니다).
- **사진 없이는 완료 보고가 안 됩니다.** 완료 보고를 누르는 순간 발주처·피해자에게
  「공사가 끝났다」는 통지가 나가고 그 시각이 **하자보증 기산점**이 됩니다.
  현장을 떠난 뒤에는 사진을 다시 찍을 수 없으니, 협력사에 미리 안내해 두십시오.
- **2차 공고의 「최소 금액」은 있을 수도 없을 수도 있습니다.** 보상담당자 가견적이 있으면
  그 값이, 없으면 표준단가 개산 하단이 최소 금액이 됩니다. 둘 다 없으면 화면이
  「하한 없음」이라고 표시합니다 — 그때는 사진과 실견적을 보고 판단하시면 됩니다.
- **최저가가 아닌 업체를 고르면 사유를 적어야 합니다.** 낙찰·변경견적 재경매 모두
  같습니다. 적은 사유는 감사 기록에 남아 나중에 근거가 됩니다.
