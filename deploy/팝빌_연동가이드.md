# 팝빌 문자·알림톡 연동 가이드

㈜올림포스네트웍스 전략사업실 유경탁 파트장

코드는 이미 다 연결되어 있다. **아래 값 4개를 받아서 .env 에 넣고 재시작하면
그 순간부터 문자가 실제로 나간다.** 그 전까지는 지금처럼 모든 알림이
발송대기함에 '발송대기'로 쌓이고, 담당자가 수동 처리한다.

---

## 1. 팝빌에서 받아야 하는 것 (총 소요 1~3일)

| 순서 | 할 일 | 어디서 | 소요 |
|---|---|---|---|
| ① | 팝빌 회원가입 (사업자번호 656-87-02554) | popbill.com | 즉시 |
| ② | 연동인증 키 발급 — **LinkID / SecretKey** | 팝빌 > 연동관리 > 연동인증 관리 | 즉시 |
| ③ | **발신번호 사전등록** — 회사 대표번호 등 | 팝빌 > 문자 > 발신번호 관리 | 통신사 심사 1~2일 |
| ④ | 문자 충전 (선불) 또는 자동충전 설정 | 팝빌 > 충전 | 즉시 |

> 발신번호 사전등록은 법정 의무(전기통신사업법 §84의2)다. 등록 안 된 번호로는
> 운영 발송이 거부된다. ③이 전체 일정의 병목이니 가장 먼저 신청할 것.
>
> **⚠ 테스트베드에도 발신번호를 따로 등록해야 한다.** 운영 계정과 별개다.
> 테스트베드는 과금·실수신이 없을 뿐, 발신번호 검사는 똑같이 한다 —
> 여기서 가장 많이 막힌다.

## 2. .env 에 넣기

> ⚠⚠ [라운드310] 아래 블록을 그대로 복사해 붙여넣지 말 것 — 원래 `←` 로
> 값 뒤에 설명을 달아 뒀었는데, `.env` 파서(envload.py)는 `#` 로 시작하는
> 주석만 알아본다. `←` 는 그대로 값의 일부가 되어 `POPBILL_TEST`가 문자열
> `"1"`이 아니게 되고, `"1"`이 아니면 코드는 **운영(실발송·과금) 모드**로
> 읽는다(정확히 이 가이드가 막으려는 그 사고). 설명은 `#` 로 시작하는
> 별도 줄에 둔다(진짜 `.env` 파일 자신이 이미 이 방식을 쓴다).

```
POPBILL_LINK_ID=발급받은_LinkID
POPBILL_SECRET_KEY=발급받은_SecretKey
POPBILL_CORP_NUM=6568702554
POPBILL_SENDER=사전등록된_발신번호
# 처음엔 반드시 1 (테스트베드) — 0 이면 실발송·과금
POPBILL_TEST=1
# 발송 마스터 스위치
BOKGUON_NOTIFY_ENABLED=1
```

패키지 설치 후 서비스 재시작:

```bash
pip install -r requirements.txt
```

## 3. 연동 확인 (테스트베드에서)

**먼저 이것부터 돌린다.** 어디까지 됐고 어디서 막혔는지 한국어로 알려 준다:

```bash
python popbill_check.py
```

키 확인 → 연동인증 → 회원 등록 → **발신번호 등록** → 잔액 순으로 짚어 준다.
팝빌 오류 코드(`-99004` 등)를 사람 말로 바꿔 주므로, 실패해도 무엇을 고칠지 바로 안다.

전부 통과하면 실제로 한 통 보내 끝까지 확인한다(테스트베드면 과금·실수신 없음):

```bash
python popbill_check.py --send 010XXXXXXXX
```

그 다음 화면에서도 확인한다:

1. 어드민 콘솔 > **발송 대기함** — 우측 상단 카드가 "팝빌 실발송: 테스트베드"로 바뀌었는지 확인
2. **테스트 발송** 버튼 → 본인 휴대폰 번호 입력 → "팝빌 문자(SMS) 접수 …" 응답이 오면 연동 성공
   (테스트베드라 실제 문자는 안 온다 — 팝빌 테스트베드 사이트에서 접수 내역 확인 가능)
3. **지금 발송** 버튼 → 대기 중이던 알림톡·문자 건이 도달/실패로 갈리는지 확인

## 4. 운영 전환

테스트베드에서 접수가 정상 확인되면:

```
POPBILL_TEST=0
```

재시작하면 실제 발송(과금)이 시작된다. 카드에 "운영"으로 표시된다.

## 5. 동작 방식 (운영자가 알아야 할 것)

- **언제 나가나**: 예약 실행(`python manage.py sweep`, 작업 스케줄러 등록분)마다
  자동 발송 + 발송 대기함의 "지금 발송" 버튼으로 즉시 발송.
- **누구에게**: 협력사 → 협력사 등록 전화번호, 보험사 → 담당자 번호,
  피해자 안내 → 사건의 피해자 번호. **번호가 없으면 즉시 '실패'로 표시**되고
  사람이 처리한다(지어내서 보내지 않는다).
- **실패하면**: 발송 오류는 3회까지 자동 재시도 후 '실패'. 실패 건은 발송
  대기함에서 사유와 함께 보이고 '처리함'으로 닫는다.
- **90바이트 초과** 메시지는 LMS 로 자동 전환된다(단가 차이 있음).
- **데모 데이터는 절대 발송되지 않는다** (is_demo 차단).
- **48시간 넘은 대기 건은 자동 발송하지 않는다** — 연동을 처음 켜는 날,
  그동안 쌓인 옛 안내가 한꺼번에 뒤늦게 나가는 사고 방지. 옛 건은
  발송대기함에서 사람이 확인 후 '처리함'으로 닫는다.
- **일시 정지**: 키를 지울 필요 없이 `BOKGUON_NOTIFY_ENABLED=0` + 재시작.

## 6. 알림톡 전환 (선택, 나중에)

알림톡은 카카오 심사가 필요해서 문자보다 오래 걸린다:

1. 카카오 비즈니스 채널 개설 + 팝빌에 채널 연동
2. 템플릿 등록·승인 (카카오 심사 2~3일, 고정 문구+변수만 허용)
3. `.env` 에 `POPBILL_ATS_TEMPLATE=승인받은_템플릿코드`

설정하면 '알림톡' 채널 건은 알림톡으로 나가고, 알림톡 실패 시 팝빌이
문자로 자동 대체발송한다(AltSendType=C). 템플릿 없이도 문자로는 다 나가므로
서비스 오픈을 막지 않는다.

## 7. 비용 (2026-07 팝빌 공시가 기준, 부가세 별도)

| 종류 | 건당 |
|---|---|
| SMS (90바이트) | 9~11원대 |
| LMS (2,000바이트) | 27~30원대 |
| 알림톡 | 6~8원대 |

월 1만 건 기준 문자만 써도 10~11만 원 수준. 알림톡 전환 시 약 30% 절감.
정확한 단가는 팝빌 영업 협의(볼륨 할인)로 확정할 것.
