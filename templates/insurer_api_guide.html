1. 무엇을 하는 연동인가

발주처 시스템에서 기타피해물 복구 건을 접수하고, 그 건의 진행 상태와 확정 금액을 조회합니다. 화면에서 직접 등록하셔도 되고, 연동으로 넣으셔도 됩니다 — 둘은 같은 사건이 됩니다.

복구온은 시공 업체를 모아 경쟁시키고 진행을 관리합니다. 금액을 확정하거나 협상하지 않으며, 손해액을 산정하지 않습니다. 낙찰 승인은 언제나 발주처가 하십니다.

2. 인증

서버 대 서버 호출이며 API 키로 인증합니다. 브라우저 쿠키를 쓰지 않습니다. 키는 복구온 담당자가 발급해 전달합니다.

헤더X-API-Key: 발급받은키
기준 주소{{ base }}
형식요청·응답 모두 application/json (UTF-8)
키가 노출되었다고 판단되면 즉시 알려 주세요. 폐기하고 새 키를 드립니다. 폐기된 키로 온 요청은 401 로 거절됩니다.

3. 연동 확인 (가장 먼저 해보실 것)

curl -H "X-API-Key: 발급받은키" {{ base }}/api/v1/ping

{"ok": true} 가 오면 키와 통신이 정상입니다.

4. 사건 접수

POST {{ base }}/api/v1/cases
Content-Type: application/json
X-API-Key: 발급받은키

{
  "category": "가드레일·방호울타리",
  "address": "서울시 강남구 …",
  "est_price": "1000000",
  "victim_name": "홍길동",
  "victim_phone": "010-0000-0000",
  "note": "야간 사고, 통행 지장 있음"
}

응답에 접수번호가 담겨 옵니다. 이후 조회는 이 번호로 하십니다.

category공종. 정해진 12개 명칭 중 하나를 정확히 보내야 합니다 — 예: 가드레일·방호울타리 · 유리·샷시·자동문 · 셔터·차단기·게이트 · 누수·배관·설비
address현장 주소. 업체 배정과 거리 계산에 씁니다.
est_price가견적(원). 필수 — 입찰 상한 기준입니다. 숫자만 보내거나 콤마를 섞어도 됩니다(예: "1000000", "1,000,000").
victim_name / victim_phone연락처를 주시면 피해자에게 진행조회 링크가 나갑니다. 없으면 생략하셔도 됩니다.
note현장 전달사항. 업체에게 그대로 전달됩니다.

5. 진행 조회

GET {{ base }}/api/v1/cases/접수번호
X-API-Key: 발급받은키

현재 상태 · 확정 공사대금 · 진행율 · 정산 상태가 내려옵니다. 목록은 GET {{ base }}/api/v1/cases 입니다.

이 응답의 금액은 시공 도급 금액입니다. 보험금 지급액이나 손해액이 아닙니다.

6. 변경 알림 받기 (선택)

상태가 바뀔 때 발주처 주소로 알려 드릴 수 있습니다. 받으실 주소를 알려 주시면 등록합니다.

보내는 사건{{ events|join(' · ') }}
형식{"event": "…", "case_no": "…", "occurred_at": "…", "data": { … }}

모든 요청에는 본문 위·변조를 확인할 수 있도록 서명이 함께 옵니다. 웹훅 주소를 등록할 때 드리는 서명 비밀키로 직접 재계산해 대조하십시오.

서명 헤더X-Bokguon-Signature: sha256=<서명값>
계산 방법HMAC-SHA256(비밀키, 요청 본문 원문) 의 16진수 표현
비밀키가 노출되었다고 판단되면 알려 주세요. 웹훅 주소를 다시 저장하시면 같은 값을 다시 확인하실 수 있습니다(주소를 바꾸지 않아도 값은 그대로입니다).

7. 오류 응답

401키가 없거나 폐기되었습니다.
400필수 값이 빠졌거나 형식이 맞지 않습니다. 어떤 항목인지 함께 알려 드립니다.
403전산 연동이 잠시 꺼져 있습니다. 복구온 담당자에게 문의해 주세요.
404그 접수번호의 사건이 없습니다.
429짧은 시간에 요청이 너무 많습니다. 잠시 뒤 다시 보내 주세요.

8. 연동 시작 순서

  1. 복구온에서 키 발급 — 담당자에게 요청하십니다.
  2. ping 확인 — 위 3번.
  3. 시험 사건 1건 접수 — 실제 현장이 아닌 건으로 넣고, 화면에서 보이는지 함께 확인합니다.
  4. 조회 확인 — 접수번호로 상태가 오는지 봅니다.
  5. 이상 없으면 실사건 전환.
